# Feature specifications

Each meaningful increment starts with one focused Markdown specification in this directory. Use a descriptive lowercase kebab-case filename, for example `vehicle-movement.md`.

A feature specification should contain:

1. Purpose
2. Player-visible behavior
3. Functional requirements
4. Acceptance criteria that can be observed or tested
5. Explicit non-goals
6. Technical constraints and relevant units
7. Manual verification steps for visual or handling behavior
8. Open decisions requiring user input

Keep specifications about intended behavior. Implementation status and test results belong in the task handoff and version history, not as unsupported claims in the specification.
